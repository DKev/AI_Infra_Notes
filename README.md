# AI_Infra_Notes

记 **AI 基础设施** 的学习笔记和能复现的实验。训练、推理、数据/平台、硬件、可观测都碰，不锁一个栈；重点是**问题是什么、工具边界在哪**。

## 这仓怎么用

| 目录 | 用途 |
|------|------|
| [topics/](topics/) | 按主题写：概念、对比、用自己的话复述 |
| [labs/](labs/) | 小实验、Notebook、脚本、能跑通的最小配置 |
| [resources/](resources/) | 论文/文章/课程索引，方便以后搜、再打开 |
| [cheatsheets/](cheatsheets/) | 真会再查的命令、工具、调参，随用随加 |
| [assets/](assets/) | 图、架构示意，笔记里引用 |

## 学习地图（都想碰、可并行）

- **基础**：单卡/单机训练、推理、简单 profiling；**用什么框架就记什么**
- **训练扩展**：多机多卡、并行、通信、checkpoint/弹性、效率和显存
- **推理与在线服务**：批、延迟/吞吐、量化、各 serving 栈**能干什么**（先不必绑死一个）
- **数据与 MLOps**：数据管线、实验跟踪、训练到部署怎么串
- **硬件与系统**：GPU/网/存、成本和利用率、容量
- **可观测与可靠性**：监控、SLO、排障、变更和回滚

`topics/` 里编号只是**大致顺序**，可以穿插；`labs/` 跟某块 topic 同步做就行。

## 笔记规矩（自勉）

- 每个 `topics/*/` 里尽量**一个入口**（如 `README.md`）当目录
- 写到哪里，链到 `labs/` 具体路径或别的 topic，**别单文件爆长**
- 大文件、权重、密钥不进仓；**只写说明或脱敏名**
